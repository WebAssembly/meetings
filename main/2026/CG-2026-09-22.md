#### Relaxed dead code validation (Conrad Watt, 30 minutes)

CW: Yes. So I don't have slides, but I'm just going to screen share the [issue](https://github.com/WebAssembly/spec/issues/2235), and we can talk about it.

CW: I'll give the background to relaxed dead code validation first. This is a very old proposal that was originally proposed as part of my anger over having to understand the 1.0 type systems approach to dead code.

CW: Which was very strange and involved this little constraint system based on bottom types that didn't actually show up in the type annotations themselves. But in order to correctly type dead code, your type checker needed to maintain this extra complicated view of what a type was.

CW: So I wrote this proposal essentially to try and get rid of as much of that as possible. But we actually went the opposite way since then and embraced the bottom type, making it part of the specification in a more first-class way. So a lot of the original motivation for this proposal actually no longer applies, because we essentially went in the opposite direction, and instead of trying to get rid of bottom types as a concept, we kind of canonized them everywhere, so they're now just in the spec to explain how refs work more accurately.

CW: There was another value to this proposal, which is what Thomas is hooking into with this issue.

CW: Which was, if you have certain checks that you really can't be bothered doing in dead code because you don't have—

CW: We believed, and I think we've found a few instructions where this isn't true, that we weren't really going to do too much complicated typing calculation based on looking at the types that we're popping off the type stack during validation. We kind of believed that we'd have enough annotations that you don't really need to do that. And then we gradually weakened that belief as we added more GC instructions. And now I think with Thomas's issue, we're finding a few examples of instructions.

CW: Really, you can't just do the type checking from the annotations. You need to pop the value off the type stack during validation, look at it, and then decide what you're going to do. And one of the things this proposal gave you was a hook for defining alternative versions of typing rules in dead code.

CW: Where you could turn that off because you didn't have a real type to pop from the type stack, but you were doing something else instead.
