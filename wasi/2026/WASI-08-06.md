Bailey: while we're iterating on a feature, we might experiment with it. But not ship it. We had a really good test run with fixed-length lists. 

> https://github.com/WebAssembly/WASI/issues/944

Bailey: this feature has been around for a long time in the component model repo. But there's been an evolution of the concept of bounded lists. Changed the approach, given it's still evolving we closed the issue and promised to look at it again once it was ready to adopt.

Bailey: would like us to vote on one which is ready; the `map` type. Presented on this in the last WASI meeting. Only difference is that I got Jortis to push C++ over the line to fill out the table.

Bailey: the process we've established is that once we believe it's stable, has had feedback, and stable in the component model we can **vote to adopt it**. Once adopted, starting from the next release WASI proposals can begin to depend on it.

## Vote: Adopt Component Model implements annotations

Bailey: This one is similar to maps, as it affects guest bindings. But also host bindings and affects the ABI. It is stable in the component model, with a lot of feedback across many projects and seems to be working well. Has been very useful for the work I've been working on.

Bailey: similar to other WASI APIs, not seen it used yet in existing proposals. Things like blob store, kv, config really need these to work well. This will enable those proposals to work without needing additional workarounds.

Lann (in chat): We ended up designing around its absence I think. `wasi:http` too https://github.com/WebAssembly/WASI/blob/a72eb0926f05c912a81bcd6dde6c1e0231878c30/proposals/http/wit/worlds.wit#L104-L108.
