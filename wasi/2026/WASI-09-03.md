## Triage

### signal handling ([#166](https://github.com/WebAssembly/WASI/issues/166))

Victor: Signal handling seems like an intense thing to standardize, especially since signals aren't standard.

Pat: Dan left a comment which AFAIK is still definitive. This requires massive changes which would require core Wasm semantics changes. We shouldn't do that in this group.

Luke: Agreed, especially trap handling.

Pat: There's no realistic way to make changes in the core Wasm spec to do that.

Luke: Or if there was, that would be up to the core Wasm group; we shouldn't try and take that and run with it. SIGSEGV stuff we shouldn't want to handle. But there are other things we might want to handle: SIGCHLD, SIGPIPE — if we had shared exports (?) we could potentially implement signal handling, because it's sort of like shared functions.

Pat: The current consensus is: 1) if you want to intercept loads/stores, please bring that to the core Wasm group; 2) right now we have no reason to expect shared-everything threads won't reach stage 4. Shared export functions would be the way we semantically suggest we handle signal handling.

### [Pre-proposal] State Continuity Profiles for WebAssembly Components ([#946](https://github.com/WebAssembly/WASI/issues/946))

Bailey: This one was opened fairly recently.

Lann: Process question: to me it seems very clear that this is not a WASI question. Instead of closing it, should we consider transferring this to an appropriate place?

Luke: Sounds reasonable.

Bailey: Can we move this issue to the component model?

Luke: Not sure I understand it, but sure.

Pat: The author built a component model implementation on top of Wazero: https://github.com/chenty2333/wacogo

Bailey: I don't want to move this one right away; I want to digest it a bit more. It's a little dense, but the motivation behind it seems reasonable. I feel a little guilty transferring this one straight away.

Pat: We can concretely say that the component model doesn't have what the author is asking for. Does anyone want to collaborate with them on this? I don't have a business reason to work on this; it's very much a birds-of-a-feather thing.

Merlijn: We had this experimental runtime for Kubernetes where we ran Kubernetes operators that we suspended to disk when there were no changes to be processed, and spun them up as needed. We ran into some problems trying to suspend these; the memory of every single component needed to be written to disk. We're no longer interested in working on this.

Pat: Wasmtime now has the Wizer project in its repo, which can suspend components. It takes the component and adds accessors that can extract all the necessary state. That covers globals and memories. Resources can only be obtained after they've been instantiated; same for refs. None of that works. So: some parts of this are a solved problem. The parts which are not are hard for a good reason.

Merlijn: My main piece of feedback on this is that it's more something we expect runtimes to solve than something we should standardize. We want runtimes to have the flexibility in how they solve this and allow them to decide how to optimize it.

Bailey: Could you post that on the issue?

Merlijn: For sure.

### WASI Serial API ([#350](https://github.com/WebAssembly/WASI/issues/350))

Bailey: Seems like it was closed as completed? Is this SPI?

Merlijn: We do have a USB API. Maybe they mean a generic serial device?

Bailey: How would that intersect with the general SPI proposal?

Merlijn: Good question. From an OS perspective, a generic serial device does exist, but on the physical level I'm unsure whether it does. The way they would interact is that an SPI device — we would be able to turn an SPI device into a generic serial device. We can always add more abstractions at the OS level. We need to do more investigation to see whether we can/want to layer this on USB or other existing protocols.

Lann: Unsure whether this is incredibly broad or simple — e.g. a generic byte stream.

Bailey: Can you do a pass on this and investigate?

Merlijn: Yes! Can you assign it to me?
