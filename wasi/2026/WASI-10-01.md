### Structured Annotations

**Yordis**: Two issues open in the component model. One is for top-level types. The spec is there, I made it work as best I could in wasm-tools with the majority of changes being testing. I have it working with wit-bingen.

**Yordis**: I have been chasing for almost 3 years now to create a superset of protobuf. I want to be able to share these components and share marshalling. In protobuf we have a way to define values for fields from the OpenAPI it comes from an annotation. They have semantic for what they can do with the fields.

**Yordis**: They even have cell syntax where they even have programming inside the annotation. I know this is probably what will raise concerns.

I want to add metadata for policies and the metadata for what I would need. In nats events, I aim to codegen the implementation in the client and backend. You may have a type that is an error but I can enhance it with semantic meaning.

The annotation is just a type that you declare. `@annotation()`. I researched how java and csharp use this then you can use annotate to pass structured information into it. It is type safe, there is not a string. From the WIT perspective you do have the types for it. Questions?

**Yosh**: The site you just showed, what is it?

**Yordis**: claude.ai artifacts. I can post that yeah if you want to use it.
